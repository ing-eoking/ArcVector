# 복제

## 문제

인덱스 하나가 두 벌로 존재한다.

- **벡터 원소** — arcus Map에 있다. arcus가 알아서 복제한다.
- **HNSW 그래프** — 우리 프로세스 메모리에 있다. arcus는 존재조차 모른다.

그래서 승격된 노드는 벡터를 다 갖고도 탐색할 그래프가 없다. 예전엔 첫 읽기 때 Map 전체를 훑어 처음부터 지었고, 큰 인덱스면 수 분이 걸렸다.

## 해결 — 식별자만 보낸다

마스터가 `vadd`를 처리하면 두 갈래로 나간다.

```
마스터                                복제본
  │
  ├── arcus 복제 ──────────────►  Map에 원소 도착 (벡터 포함)
  │
  └── 우리 채널 ───────────────►  "idx의 v42가 바뀌었다"  (id만)
       (TCP)                              │
                                          ▼
                              자기 Map에서 v42를 읽어 그래프에 삽입
```

**벡터는 우리 채널로 절대 안 보낸다.** 복제본은 "어디를 보라"는 말만 듣고 자기 Map에서 읽는다.

두 갈래는 별개 연결이라 **순서가 보장되지 않는다.** 델타가 원소보다 먼저 올 수 있다. 그때는 미뤄뒀다 다시 시도한다.

## 누가 마스터인가

설정으로 받지 않는다. 10초마다 데몬에게 직접 묻는다.

```
stats replication  →  STAT mode  master | slave | alone | disabled
```

`slave`면 복제본, 나머지는 마스터. 같은 질문이 **스위치오버 감지**도 겸한다 — 강등되면 다음 비트에 `slave`가 보인다.

마스터는 자기 주소를 `AV OWNER` 키에 적고, 그 키가 arcus 복제를 타고 복제본에 간다. 복제본은 그 주소로 연결한다. 낡은 주소로 잘못 찾아가면, 그 노드가 "나 마스터 아니다, 저기다" 하고 알려준다.

## 어긋나면 고친다

복제본에선 그래프와 Map의 개수가 **정상적으로도** 다르다.

- 스트림이 조금 뒤처지면 → 그래프가 **적다**
- id가 갱신되면 arcus가 원소를 새로 만드는데 그래프는 옛 주소를 쥐고 있어서 → 그래프가 **많다**

예전엔 어느 쪽이든 그래프를 통째로 버리고 재구축했다. 그래서 쓰기가 흐르는 동안 복제본이 영원히 수렴하지 못했다.

지금은 차이만 고친다.

```
Map에 있고 그래프에 없음  →  넣는다
그래프에 있고 Map에 없음  →  뺀다
```

## 한계

- 쓰기는 복제본 ack를 기다리지 않는다 (sync 복제로 구성해도).
- **재시작**은 여전히 차갑다. 그래프를 저장하지 않으므로 Map에서 다시 짓는다. *스위치오버*만 따뜻하다.
- 실제 노드 쌍에서 돌려본 적이 없다.
